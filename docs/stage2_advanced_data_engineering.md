# Stage 2 assessment: Advanced Data Engineering learning lab

**Status:** Proposed for approval. No Stage 2 code or dependencies are implemented by this assessment. Keep the serving application a modular monolith. Each tool remains a separate, bounded experiment unless evidence justifies promotion.

## Design rule

Stage 1 already provides a deterministic CSV batch pipeline, source validation, fingerprints, a guarded migration path and local PostgreSQL integration. The current 110,578-row full source completes locally in seconds. Stage 2 therefore demonstrates why and how data-platform tools work; it is not a rewrite justified by current scale. Keep experiments under `experiments/data_engineering/`, use separate dependency environments/lock files, and operate only on sampled data or disposable local files. Never make these tools required for API startup.

## Phased implementation proposal

1. **2A — Parquet and DuckDB:** create a deterministic, referentially valid sample from the Stage 1 sampler; write typed Parquet, query it with DuckDB, compare exact aggregates with pandas, and record file size/time/RAM. Keep output under ignored experiment data.
2. **2B — dbt OSS models and tests:** using a dedicated environment and a free local adapter that is verified at implementation time, build staging and mart models, dependency lineage, schema/data tests and documentation. Reconcile results against Stage 2A and preserve deterministic outputs.
3. **2C — Airflow orchestration:** after the standalone commands work independently, make a small local WSL2 DAG call them as processes. Test retry, task failure, rerun idempotence and cleanup. Keep credentials out of DAG files and do not share the benchmark database.
4. **2D — Kafka event replay:** use a separate WSL2 single-node KRaft demo to convert a small ratings sample into events. Test partition-key ordering assumptions, consumer offsets, restart/replay and idempotent sink behavior. Do not route events into the app database.
5. **2E — PySpark comparison:** on a bounded Parquet sample, reproduce a selected DuckDB/pandas aggregation in Spark local mode. Measure startup-inclusive and steady job time separately, peak memory, and output parity. Document where Spark overhead outweighs distribution for this dataset.
6. **2F — Review and disposition:** compare setup burden, correctness, runtime, storage and peak memory; retain all as labs unless a real product need and promotion gate are approved. Do not change API contracts or required application dependencies in Stage 2 without a separate review.

Run the tools sequentially, not all together. First check free disk and WSL2/Java availability. Start with the DuckDB/Parquet phase; stop and resize the sample if memory approaches the laptop limit. Airflow and Kafka are the heavier local services. Existing sample sizes are up to 100,836 ratings, but the first Spark/Kafka/Airflow exercises should use a much smaller sample until measured.

## Stage 2 approval gate

No dependencies, services, environments, DAGs, topics, analytical schemas or application changes have been created. Before implementation, approve one bounded phase and its sample, runtime/resource limit, environment isolation and acceptance measurements. Check versions, adapter support, licenses and current install instructions again at that time; the linked vendor/project docs are live and may change.
